# Iconography

## Rules

1. **Reuse before reaching for new.** Check the existing icon set first. Only introduce a new icon when no existing one carries the meaning — one concept, one glyph, everywhere.
2. **Simplified shapes, minimal detail.** Use the fewest strokes and shapes needed to read the metaphor. Detail that disappears at 16px is noise; strip it out.

## Reuse existing icons

One concept should map to one icon across the product. If "delete" is `Trash` in a table row, it stays `Trash` in the dropdown and the confirmation dialog — never swapped for `XCircle` or a bespoke bin.

## Simplified shapes

Icons are read at a glance — and that read fails when a glyph piles on extra shapes that don't help carry the metaphor. Both icons below mean "table", but `Table2` keeps the metaphor in a single clean outline, while `TableProperties` splits the frame into a denser grid of lines that turns muddy at 16px.

## In context

These rules are why a button toolbar reads cleanly even at a glance — every glyph is one of the household set, and each one survives the small size the button forces it into.
