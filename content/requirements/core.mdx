# Core Ingredients of Requirements

1. **Problem Overview**
2. **Solution** — short summary *(optional)* with high-level diagram
3. **Stories** — stories in flow order
   - 3.1 Story
   - 3.2 Diagrams / wireframe sketches *(optional)*
   - 3.3 Acceptance criteria (with field validations; story-specific out-of-scope here too)
4. **Out of scope** — solution-level *(optional)*
5. **Open questions** *(optional)*
6. **Timeline**

## 1. Problem Overview
Consice description of the problem/feature.

## 2. Solution
Short summary of the solution, with a high-level diagram. 
Summary is optional, Use it when it adds value. The diagram is preferred, but if the solution is simple enough, you can skip it. Use proper type of diagram (flowchart, sequence, state, etc.) based on the solution. But you are not bound to these types. If you have a better way to communicate the solution, use that.

## 3. Stories
Stories are mentioned in flow order. 
Each story has:
- Story - As a [persona], I want to [action], so that [outcome].
- Diagrams / wireframe sketches *(optional)* - Use them when they add value. They are preferred when the story is complex enough that it cannot be easily understood without them. Use proper type of diagram (flowchart, sequence, state, etc.) based on the story. But you are not bound to these types. If you have a better way to communicate the story, use that.
- Acceptance criteria 
with:
    - Field validations (if any)
    - Story-specific out-of-scope (if any)

## 4. Out of Scope
Solution-level out-of-scope items. Use them when they add value. They are preferred when there are significant out-of-scope items that need to be explicitly mentioned. If there are no significant out-of-scope items, you can skip this section.

## 5. Open Questions
Use this section to list any open questions that need to be answered before the solution can be implemented. Use it when it adds value. It's preferred when there are significant open questions that need to be explicitly mentioned. If there are no significant open questions, you can skip this section.

## 6. Timeline
Use this section to provide a high-level timeline for the implementation of the solution.
