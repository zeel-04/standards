# Voice

## Rules

1. **Direct, not chatty.** Say what's true. Don't apologise, hedge, or over-explain.
2. **Second person ("you"), present tense.** "You haven't assigned anyone yet" — not "Users need to assign someone."
3. **Active voice.** "You submitted this request" — not "This request was submitted".
4. **Plain English over domain jargon.** If a term is specialised, define it once or link to a glossary.
5. **No exclamation marks.** Not in buttons, not in toasts. Confidence doesn't need punctuation.

## Voice vs tone

- **Voice** is constant — this rulebook.
- **Tone** flexes with context — celebratory on first success, reassuring on a blocking error, neutral on routine actions.

### Tone matrix

| Context | Tone | Example |
|---|---|---|
| Routine action confirmed | Neutral, flat | "Changes saved." |
| First-time / milestone success | Light, still factual | "First request submitted. An approver will take a look." |
| Non-blocking warning | Measured | "This request is above your team's weekly limit. You can still submit it." |
| Blocking error | Direct, helpful | "We couldn't submit. Your connection dropped — try again when you're back online." |
| Destructive confirm | Direct, consequence-first | "Deleting removes the request and its receipts. This can't be undone." |
| Permission / access denied | Factual, no blame | "You don't have access to this workspace. Ask an admin to invite you." |
| Empty state (first use) | Orienting | "No requests yet. When someone on your team submits, it'll show up here." |
| Onboarding prompt | Inviting, not pushy | "Add a payment method to start issuing reimbursements." |

## Do / Don't

**Do**
- Say what's true in the fewest words that still read as human.
- Use contractions ("you're", "can't") — they keep voice friendly without getting chatty.
- Read copy out loud. If it sounds like a form letter, rewrite.

**Don't**
- Don't apologise for routine UI outcomes. "Sorry, this field is required" → drop the "Sorry".
- Don't hedge ("it seems like", "unfortunately"). State it.
- Don't use "please" in button labels or validation. "Please enter your email" → "Enter your email".
- Don't switch to third person ("The user must…") in UI copy. Stay with "you".
