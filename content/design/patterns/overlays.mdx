# Overlays

Modals and sheets both keep users in context without navigating to a new page. Fit determines which to use: the more content and steps an interaction carries, the more space the overlay needs.

## Rules

1. Use an overlay, not a new page, when a task is secondary to what's behind it. Navigate to a page when the content is a destination in its own right.
2. Use a modal when the content fits one desktop screen without scrolling — a confirmation, a short form, or a single focused action.
3. Use a sheet when the content needs to scroll — a long or multi-step form, or a record edited inline alongside a list.
4. Never nest a modal inside another modal. If a triggered action needs more space, escalate to a sheet.
5. Close a modal with a clear dismiss action or backdrop click; close a sheet by sliding it away.

A confirmation dialog is a modal — see [Confirmations](/design/patterns/confirmations) for its content and button rules.
