# Confirmations

## Rules

1. **Confirm only destructive and irreversible actions.** Deleting, rejecting, archiving. Never confirm "Save", "Submit", or any additive action.
2. **Mirror the consequence in the title and the confirm button**, not "Yes / OK" (`Delete` → title "Delete request REQ-2039?", button `Delete request`).
3. **Put the destructive button on the right**, styled `destructive`. Cancel is on the left, styled `ghost` or `outline`. Reserve `destructive` styling for destructive actions — a "Publish" confirm is a primary action.
4. **Name the entity and the consequence.** "Delete request REQ-2039? This can't be undone" — so the user confirms the right one.
5. **Prefer undo over confirm** when the action is reversible. Delete immediately, surface an undo toast for 8–10s. Never offer confirm and undo together.
6. **Never stack confirms.** One confirm, then act.

## When to use each pattern

| Pattern | Use when |
|---|---|
| Inline confirm (expand in place) | The action is light but worth a second look |
| Dialog confirm | The action is destructive and undo isn't feasible |
| Undo toast | The action is reversible (most deletes with soft-delete) |
| No confirm | The action is safe, reversible, and obvious |

## Copy examples

### Before / after

| Weak | Strong |
|---|---|
| Title: "Are you sure?" / Button: "Confirm" | Title: "Delete request REQ-2039?" / Button: "Delete request" |
| Title: "Delete?" / Body: "This action cannot be undone." | Title: "Delete user alex@acme.test?" / Body: "They'll lose access immediately. Their submitted requests stay in the system." / Button: "Delete user" |
| Title: "Reject?" / Button: "Yes" | Title: "Reject this request?" / Body: "The requester will be notified and the request closes. You can add a note below." / Button: "Reject request" |
| Button: "OK" / "Cancel" | Button: "Archive project" / "Keep project" |

```tsx
      </AlertDialogAction>
    </AlertDialogFooter>
  </AlertDialogContent>

```

### Undo toast template

For reversible actions, skip the confirm — act, then offer undo.

<Preview>
  <UndoToastDemo />
</Preview>

```tsx
function archiveRequest(id: string) {
  optimisticallyArchive(id)
  toast('Request archived', {
    action: {
      label: 'Undo',
      onClick: () => restore(id),
    },
    duration: 8000,
  })
}
```
