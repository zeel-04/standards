# Color roles

Color roles describe the *intention* behind a color. Apply them to actions and UI states so the same hue always means the same thing — primary, secondary, warning, or dangerous.

## Rules

1. **Pick by role, not hue.** Reach for `brand` or `danger`, never for "blue" or "red". The token decides the color.
2. **One role per surface.** A button is brand *or* danger, never both. Two competing roles in the same view dilute both.
3. **Neutral is the default.** Most UI is neutral. Reserve coloured roles for the moments that need them — primary action, warning, error.

## The roles

| Role | Swatch | Use for |
|---|---|---|
| `neutral` | <span className="inline-block size-3 rounded-full bg-neutral-300 align-middle" /> | Default text and secondary UI — secondary buttons, navigation, body copy. |
| `brand` | <span className="inline-block size-3 rounded-full bg-blue-500 align-middle" /> | Primary actions and brand-forward moments. One per view. |
| `success` | <span className="inline-block size-3 rounded-full bg-green-500 align-middle" /> | Favourable outcomes — success toasts, completion checkmarks. |
| `warning` | <span className="inline-block size-3 rounded-full bg-amber-400 align-middle" /> | Caution to prevent a mistake — "you have unsaved changes", destructive-but-reversible actions. |
| `danger` | <span className="inline-block size-3 rounded-full bg-red-500 align-middle" /> | Destructive or serious error states — delete, failed payments, blocking errors. |

## Mapping to shadcn variants

The roles map onto Button variants like this:

```tsx
<Button>Create</Button>                       {/* brand */}
<Button variant="outline">Cancel</Button>     {/* neutral */}
<Button variant="warning">Continue anyway</Button> {/* warning */}
<Button variant="destructive">Delete</Button> {/* danger */}
```

`information` and `success` show up in toasts, banners, and badges — not buttons. There's no `<Button variant="success">` because a green "Confirm" rarely earns its weight over the default brand button.
